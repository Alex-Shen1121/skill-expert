# 领域文档

本项目使用 single-context 领域文档结构。

## 开始分析代码之前

如果以下内容存在，Agent 应先阅读相关内容：

- 根目录的 `CONTEXT.md`
- `docs/adr/` 中与当前工作有关的架构决策

如果文件还不存在，继续工作即可，不需要提醒用户创建。

领域术语或重要架构决策明确后，可以再通过相关 Skill 创建这些文件。

## 文件结构

```text
/
├── CONTEXT.md
├── docs/
│   └── adr/
│       ├── 0001-example-decision.md
│       └── 0002-another-decision.md
└── src/
```

## 使用统一术语

当 Issue、测试、重构建议或代码使用领域概念时，应采用 `CONTEXT.md` 定义的名称。

不要擅自使用含义相近但名称不同的词。

如果需要的概念尚未定义，应重新检查现有代码和文档。确认确实缺失后，再交给领域建模流程处理。

## 架构决策冲突

如果计划中的修改与现有 ADR 冲突，必须明确指出冲突，不能静默覆盖原有决策。
